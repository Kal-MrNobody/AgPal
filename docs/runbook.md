# Runbook: failure and recovery paths

Every path below is covered by a test that ends in a consistent ledger (postings sum to zero, no negative cash, cached
balances = posted sums, no orphaned holds) — `packages/policy/src/chaos.test.ts`, `webhooks.test.ts`, `gate.test.ts`,
`packages/paypal/src/http.test.ts`, `notify.test.ts`.

| Failure                                                                       | What happens                                                       | Recovery                                                                                                                                                                                                     | Operator action                                                                                       |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| PayPal 5xx / timeout **mid-capture** (money taken, response lost)             | `Commerce.capture` throws; nothing booked                          | Retry uses the same `PayPal-Request-Id` (`capture:<orderId>`); PayPal returns the original capture; booked once (`paypal:capture:<id>`). The `PAYMENT.CAPTURE.COMPLETED` webhook books it too, idempotently. | None. If neither retry nor webhook arrives, reconciliation shows _missing in ledger_ → alert.         |
| PayPal 5xx / timeout **mid-payout**                                           | Intent `failed`, hold **kept**                                     | `gate.retry(intentId)` (Finance agent tool `retry_failed_payout`, or CLI) resends with the same `sender_batch_id` = intent id; PayPal de-duplicates; booked once.                                            | `gate.abandon(intentId)` only after confirming in PayPal that nothing was paid; it releases the hold. |
| Worker crash between ledger hold and PayPal call                              | Intent stuck `approved` with an active hold                        | Worker runs `gate.recoverStuck()` every 5 min: executes with the original idempotency key; never twice.                                                                                                      | None.                                                                                                 |
| Duplicate webhooks                                                            | Stored once (event id), processed once                             | Bookings keyed by PayPal ids; domain events deduplicated.                                                                                                                                                    | None.                                                                                                 |
| Out-of-order webhooks (refund before capture, payout returned before settled) | `RetryLaterError` → pg-boss retries 8× with backoff                | Books when its dependency lands. Final attempt still unmatched → **suspense** + critical alert; reconciliation stays red.                                                                                    | Resolve the alert: book the missing item, or reverse.                                                 |
| Payout item FAILED / RETURNED / BLOCKED / UNCLAIMED→RETURNED                  | Webhook `payout.failed`                                            | Cash-out and accrual reversed; hold released; Growth and Finance woken.                                                                                                                                      | Decide whether to retry with the contractor.                                                          |
| Double-clicked approval (UI, Telegram)                                        | Approval row locked; second click sees it decided                  | One execution. Telegram callbacks also deduplicated by callback id.                                                                                                                                          | None.                                                                                                 |
| Two agents spend one envelope at the same instant                             | Advisory lock per envelope + row-locked holds                      | At most what the envelope holds; others denied `funds.insufficient`.                                                                                                                                         | None.                                                                                                 |
| OAuth token expiry mid-run                                                    | 401 from PayPal                                                    | REST client refreshes once and retries; SDK refreshes 5 min early (`oAuthClockSkew`).                                                                                                                        | None.                                                                                                 |
| Transaction Search lag (~2–3 h)                                               | Recent ledger items have no PayPal row yet                         | `pending`; with `--live`, verified by id to the cent; mismatch only after 24 h.                                                                                                                              | None.                                                                                                 |
| Model provider outage                                                         | Agent run `failed`; hold for the run's max cost released/converted | Next heartbeat retries; money untouched (agents only create intents).                                                                                                                                        | None.                                                                                                 |
| Kill switch                                                                   | Company or agent paused                                            | Gate denies everything; scheduler skips runs.                                                                                                                                                                | `POST /api/kill-switch {on:false}` or `gate.setKillSwitch`.                                           |

## Daily checks

1. `pnpm reconcile --live` — CLEAN, or each alert explained.
2. `pnpm approvals` — nothing waiting longer than a day.
3. Alerts page in the boardroom — suspense items resolved.
