# Deploying AgPal to Render

`render.yaml` is a Blueprint: **agpal-api** (Fastify, web), **agpal-web** (Next.js boardroom, web), **agpal-worker**
(pg-boss: webhooks, agent heartbeats and wake-ups, Telegram cards, crash recovery, daily autonomy), **agpal-reconcile**
(cron, 03:17 UTC) and **agpal-db** (managed Postgres). Secrets live in the **agpal-shared** env group.

## 1. Create the Blueprint (dashboard)

1. Render → **New** → **Blueprint** → connect GitHub → pick `Kal-MrNobody/AgPal`, branch `main`.
2. Render reads `render.yaml` and asks for every `sync: false` value in **agpal-shared**:
   - `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` — the sandbox app's credentials.
   - `OPENAI_API_KEY` — the AgPal OpenAI project key (budget set on the project).
   - `AGPAL_COMPANY_ID`, `PAYPAL_WEBHOOK_ID` — leave empty for now (step 3).
     `AGPAL_ADMIN_TOKEN`, `AGPAL_SESSION_SECRET`, `AGPAL_CALLBACK_SECRET` are generated by Render.
3. **Apply.** The API runs `pnpm db:migrate` as its pre-deploy step (expand-only migrations: new columns/tables
   nullable or defaulted, no drops in the same release), then starts with health check `/health`.

## 2. Seed the demo company

Render → **agpal-worker** → **Shell**:

```bash
pnpm seed:demo
```

It runs a full simulated week in dry mode (real agents, no PayPal calls) and prints the company id. Then:

```bash
pnpm schedule:seed --company <that id>
```

Set `AGPAL_COMPANY_ID=<that id>` in **agpal-shared** → **Save, rebuild and deploy**.

## 3. Register the production PayPal webhook (no dashboard clicking)

In the **agpal-api** Shell:

```bash
pnpm webhook:register --url https://<agpal-api>.onrender.com
```

It registers `https://<agpal-api>.onrender.com/webhooks/paypal` for exactly the events in `PAYPAL_WEBHOOK_EVENTS`
and prints the webhook id. Put it in `PAYPAL_WEBHOOK_ID` (agpal-shared) and redeploy agpal-api. Until then the
endpoint fails closed (verification needs the id).

Dashboard alternative: developer.paypal.com → **Apps & Credentials** → your sandbox app → **Webhooks** → **Add
webhook** → URL above → tick the events listed in `packages/policy/src/webhooks.ts` → Save → copy the Webhook ID.

## 4. Sign in to the boardroom

In the **agpal-worker** Shell: `WEB_URL=https://<agpal-web>.onrender.com pnpm founder:link` → open the link
(valid 15 minutes) → session cookie for 12 hours.

## 5. Optional: Telegram approvals

Create a bot with @BotFather; add to agpal-shared: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
`TELEGRAM_FOUNDER_USER_ID`, `TELEGRAM_WEBHOOK_SECRET`. Then:

```bash
curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" -d url="https://<agpal-api>.onrender.com/telegram/webhook" -d secret_token="$TELEGRAM_WEBHOOK_SECRET"
```

## Logs and secrets

Fastify logs are structured JSON with redaction of auth headers, PayPal signature headers, cookies and any `secret`,
`password`, `token`, `apiKey` field. Secrets are `Secret` objects inside the apps and never printed.

## End-to-end verification checklist

- [ ] `GET https://<agpal-api>/health` → `{"status":"ok","database":true}`
- [ ] Boardroom sign-in link works; Overview shows the seeded company (cash, revenue, AI cost).
- [ ] Departments, Approvals, Ledger, Agents, Reconciliation, Schedule pages render (AG Studio watermark and Bryntum
      "Trial" badge are expected without licence keys).
- [ ] Approve a held item from the Approvals page → status executed (payout appears in the sandbox).
- [ ] A sandbox card sale (`pnpm loop:manual --auto-approve` in a Shell) → `PAYMENT.CAPTURE.COMPLETED` arrives at
      `/webhooks/paypal` (Render logs) and is deduplicated against the API booking.
- [ ] Worker logs `worker ready` and `scheduled 4 agent heartbeat(s)`; an agent run appears on the Agents page.
- [ ] CFO assistant (edit mode → AI Assistant) answers "Why did Growth overspend?".
- [ ] Next morning: the agpal-reconcile cron run is CLEAN (or each alert explained).
